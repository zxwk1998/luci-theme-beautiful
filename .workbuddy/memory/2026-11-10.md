
## luci-theme-beautiful（shadcn 风格 LuCI 主题）
- 结构：src/*.css 分层（10-tokens / 20-base / 30-layout / 40-controls / 50-surfaces / 60-luci / 70-utilities / 75-polish），
  src/vendor/00-structure.css 为官方 bootstrap cascade.css 原样结构层；node tools/build.mjs 合并输出
  htdocs/luci-static/beautiful/cascade.css，并把 sha1 前 8 位写入 header.ut 的 assetver 做缓存失效。
- 模板：ucode/template/themes/beautiful/{header,footer,sysauth}.ut，基于路由器实机 LuCI 26.304 的 bootstrap 模板接口
  （node?.css / dispatched.title / ctx.request_path），自建 sidebar + sticky topbar 外壳。
- 菜单：htdocs/luci-static/resources/menu-beautiful.js（侧边栏分组折叠 + 面包屑 + tabmenu + 深浅色切换 + 移动端 off-canvas）。
- 实机：OpenWrt 25.12.6 / aarch64_cortex-a53 / apk（apk-tools 3.0.5，无 mkpkg），已部署验证概览、系统、日志页；
  system/startup 在官方 bootstrap 下同样停在“加载视图中…”，判定为路由器 LuCI 视图侧问题，与主题无关。
- 打包：apk 需 Linux SDK 编译（本机 macOS 无 docker），已备 Makefile + root/install.sh + tools/package.sh（dist/*.tar.gz）。

## 修复 tabmenu 全部跳转报错（No page is registered at '/dropbear'）
- 根因：menu-beautiful.js render() 把 `L.url(mode, group, item)` 生成的绝对 URL 再传给 renderTabMenu，
  内部又 `L.url(url, child.name)`。LuCI 21.02+ 的 `L.path()` 会用正则
  `^(?:[a-zA-Z0-9_.%,;-]+\/)*[a-zA-Z0-9_.%,;-]+$` 过滤每一段，**以 / 开头的整串被静默丢弃**，
  只剩叶子名 → `/cgi-bin/luci/dropbear`（正确应为 `/cgi-bin/luci/admin/system/admin/dropbear`）。
  因此所有带 tab 的页面（系统→管理、网络等）点了都报错，与 dropbear 是否安装无关。
- 修复：render() 传 segments 数组；renderTabMenu 用 `L.url(...segments, child.name)` 逐个传参；
  active 判定改为 `dispatch[segments.length]`（原为硬编码 `3 + level`，仅对 4 段路径成立）。
- 兼容性坑：`L.path()` 的数组参数支持直到 LuCI 24.10（master）才有；21.02/23.05 会把数组 String 成
  `admin,system,admin,dropbear`（逗号能过正则）→ 生成错误节点名。故必须用独立参数而非数组。
- 验证：以 21.02/23.05 的 L.path 语义脚本对比三种写法（旧=/cgi-bin/luci/dropbear、数组=/cgi-bin/luci/admin,system,admin,dropbear、
  新=/cgi-bin/luci/admin/system/admin/dropbear）；再用 vm 桩加载真实 menu-beautiful.js 渲染 tabmenu，6 个 tab 的 href 与 active 全部正确。
